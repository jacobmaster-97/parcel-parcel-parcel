# 商店升級系統：建議開發優先順序

更新：2026-10-23（香港）。本輪已授權訂單／選貨UI實裝與寄貨區搬位；本文件列升級開發次序，不表示以下系統已完成。原框架詳見STORE_UPGRADE_FRAMEWORK.md。

| 優先級 | 系統 | 為什麼先／後做 | 最小交付與完成條件 |
| --- | --- | --- | --- |
| P0 | 錢包、跨日收支與持久存檔 | 所有扣款、升級、人手及分店的前置；目前重整仍清空 | 區分可用現金／累計營收，日結只一次，重整恢復、備份、存檔失敗不扣款 |
| P1 | 工具升級 | 修改範圍小，最快給玩家一次可感知成長 | 先工作鞋一級，顯示前後移速與價格；不改NPC速度、不代替選貨 |
| P2 | 貨架擴充 | 直接支持目前自由上架核心，不需立刻改地圖 | A/B/C各自4→6格；看得見加層，選貨捲動、貨位與存檔一致；不可丟失舊貨 |
| P3 | 收貨／寄貨設備容量 | 容量壓力確認後再解決，不先加重選貨負擔 | 各區獨立容量，原有貨籠美術延伸；送貨批量及寄貨預留不超收 |
| P4 | 特殊訂單 | 在擴充內容前先讓現有操作有新變化 | 首個候選同客兩件提貨，分兩次搬；一次結單、一次付錢，可退件／恢復 |
| P5 | 擴充店鋪大小 | 為額外設備和人手提供合理空間；先確認平面圖 | 一次固定擴建，保留地標、兩身位通道及手機鏡頭；擴店不自動送設備 |
| P6 | 增加人手（電腦員工） | 依賴存檔、空間、預留貨物與路徑規則，成本較高 | 首位只上架新貨，可排班；預留貨物／目的格、避讓、每日薪金只結一次 |
| P7 | 增加分店（自動營運） | 主店收支與員工模式先穩定，才有可解釋的自動經營 | 首間分店、按營業日結算淨利一次，獨立庫存，不加未批准離線收益 |
| P8 | 營運自取櫃 | 既定第三類核心玩法，需要獨立驗證，避免變成只加收入的按鈕 | 先一格：收貨→分格→入櫃→客人自取→空格回收；滿格／逾期可恢復 |

這是開發次序，玩家解鎖順序可不同。例如「擴建」可在足夠服務單數後開放，不要求玩家先買特殊訂單。工具／貨架價格、效果及收入假設仍待量測；框架中的$120／$180是示例，不是已批准平衡。

建議下一個開發切片：P0＋P1的一級工作鞋；驗證完整賺錢→收舖→購買→存檔→下一日生效，再做P2。工作鞋若未顯著改善體驗，優先完成貨架分支，不預製整棵升級樹。

P3是設備容量補充支線；若試玩沒有滿載瓶頸可延後，不應阻擋已確認八類經營成長。P5與P6順序可在一位員工不需擴建且通道驗收通過時互換；目前建議先確認空間再加AI。
