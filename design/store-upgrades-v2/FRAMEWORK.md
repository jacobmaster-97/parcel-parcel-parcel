# 商店升級功能框架 v2

2026-10-23。階段：系統／經濟文字規劃。使用者指定每日關店後先詢問是否升級，再進入貨物上架。本輪只寫框架，不修改遊戲、製作介面或發布。正式版維持v0.5.0。

本文件取代STORE_UPGRADE_FRAMEWORK.md中與本輪相衝突的流程、舊版無錢包描述、購買即自動保存及舊頁營收遷入提案。所有價格、等級、效果及解鎖門檻均待修訂確認。

## 1. 目的與每日流程

玩家用當天及往日收入，選擇改善效率、增加容量或擴展業務。主店仍保留玩家親自接客、找貨與自由上架的操作。

營業180秒 → 關店收支摘要 → 升級詢問子介面 → 查看／購買（可跳過） → 貨物上架（不限時） → 封存帳目及完整保存 → 下一天開門。

- 關店後完成現有日結處理，先顯示摘要。按「繼續」才出「今晚要升級商店嗎？」；「查看升級」進商店，「暫不升級」進貨物上架。不用強制購買，不夠錢也能繼續。
- 商店內可連買不同項目，完成後按「完成，前往貨物上架」。返回／Esc取消當前購買確認；商店頁退出等同暫不再買，不能被困在沒有可買項目的頁面。
- 升級詢問及商店皆不限時，不推進客人耐性、送貨員或營業計時；無顧客與送貨員新生成。
- 即使收貨為零，也必須先完成升級詢問；之後才按現有空收貨自動換日規則保存開門。先完成升級選擇是自動換日的必要前置。
- 建議上架階段保留「商店升級」入口，可回看及再買；不重複彈詢問。最後一件上架觸發自動換日前仍沿用現有規則，因此想再買須在完成整理前開啟。
- 建議每天都問一次，不加「永不詢問」；可一按跳過。練習不進正式升級流程，不改正式資金或能力。

## 2. 分類與可升級選項

| 類別 | 選項 | 具體改變 | 限制／階段 |
| --- | --- | --- | --- |
| 工具 | 輕便工作鞋 | 店員走路較快，縮短搬運往返 | 先做；不改NPC速度，手機保留可控性 |
| 工具 | 掃碼設備 | 縮短真實接待／交貨處理時間 | 後續驗證；現有0.4秒多為表現，不能只縮提示動畫充當效益，不自動選正確貨 |
| 工具 | 搬運工具／手推車 | 之後可一次運多件收貨 | 後期獨立設計多件持貨、選件、預留及動畫；不直接把現有一件手持改掉 |
| 貨架 | A區加層、B區加層、C區加層 | 各區4→6→8格，獨立購買 | 首批；只增格，不送貨、不改其他區，擴層有可見美術與格號 |
| 收貨設備 | 收貨籠擴容 | 6→8→10格 | 第二批；不增加送貨頻率或每批件數，預留與待卸貨容量一起檢查 |
| 寄貨設備 | 寄貨籠擴容 | 6→8→10格，含已預留位置 | 第二批；不改寄貨機率／單價；是否有滿載瓶頸需試玩驗證 |
| 空間 | 店鋪擴建 | 增加可用樓面與設備／員工安置位置 | 後期；先確認新地圖，不自動加快客流或送設備，保留至少兩身位通道 |
| 人手 | 聘請理貨員 | 電腦從收貨區搬貨到允許的A/B/C分區 | 後期；首位只上架，玩家可設定允許分區及優先序，不代替核對交貨 |
| 人手 | 員工熟練度／額外職位 | 改善工作效率、之後可多聘一人 | 首位AI及通道穩定後才做，職位與聘用分開計價 |
| 業務 | 多件提貨服務 | 同一客人需兩件，分次搬運，全部交妥才結單 | 中期可選解鎖；解鎖後可停用，不能部分交付重複領錢 |
| 業務 | 其他特殊訂單 | 預約／特殊處理候選 | 僅保留方向，具體規則及報酬另審，不同時實作全部 |
| 據點 | 第一間分店、其後分店 | 電腦自動營運，每營業日呈報收入／成本／淨利 | 後期；獨立配置與庫存，同日只結一次，不按現實離線秒數發錢 |
| 自取櫃 | 安裝自取櫃、增加格數 | 解鎖第三類核心玩法，之後加格 | 後期；先做收貨→分格→入櫃→客人自取→釋放格位，並規劃滿格與逾期 |

「跨日收入」已由v0.5基礎提供，不再列成需購買的商品。容量、速度與業務解鎖分支分開，不以一個店鋪總等級同時加所有數值。基本客流、耐性、每日180秒及單價不因購買默默調整。

## 4. 解鎖與取捨

- 第一晚：工具及貨架開放，玩家自行決定先買哪個；不設強制購買教學。
- 設備容量：完成基礎循環後開放，建議不硬性要求先買鞋；須先證明實際有滿載需求。
- 特殊訂單：以已完成服務量作熟練門檻，精確單量待定；不是購買貨架的必經前置。
- 擴建：依樓面需求、完成營業日及資金解鎖；不要求先買所有工具或特殊訂單。
- 員工：有合適職位／走道及可負擔薪金才可排班；若原店已有安全工作位置，不必為形式強制擴建。
- 分店：先完成主店管理與員工系統；自取櫃另需實際可安裝位置。日期及價錢門檻待後期試玩，不先硬定。

不要求每晚都有升級可買，也不把買不起當作失敗。未解鎖卡片顯示具體條件及進度；已實裝但尚未解鎖，與尚未製作的未開放項目要分清。

## 5. 購買、效果、收支與保存

- 升級卡顯示目前／下一級、效果前後、價格、購後可用資金、生效時點、前置條件、是否有後續每日費用。購買再確認一次，確認當下重新檢查資金／等級／分頁擁有權。
- 接受購買命令時，扣款、等級及本日投資支出於同一記憶體交易生效；連按、重試、讀檔不重買同一級。取消不變更，負數餘額禁止，不能只扣款未發效果。
- 沿用使用者已確認保存時點：購買本身不新增自動保存。介面說明「已購買（本頁生效），開下一天前保存」；到換日前把錢、能力、購買交易ID、帳簿及貨物完整一起提交。
- 換日前關頁：整份回到上次保存點，未保存收入／購買／庫存一起回退，不能留下扣款或免費升級。中途可手動匯出完整JSON；匯入必須驗證能力與相應容量，不能只匯入金額。
- 換日保存失敗：同一完整候選保持在記憶體，提示未保存，可重試／匯出；重試不再扣款。若選擇暫不保存繼續，保留既有失敗處理，停用後續新購買直到成功恢復保存能力。
- 工作鞋／貨架／貨籠確認後即供當晚整理使用；貨架原貨位與預留不變，新增空格放在原格之後，不重新配貨。下一天仍保有效果。
- 空間擴建／新職位／分店／新業務，建議下一天開門前統一套用。擴建須預先驗證新座標／路線與手持預留可保留，未通過不得接受交易；開門前保存的是已套用、可驗證的完整狀態。
- 升級記本日「投資支出」，服務收入與累計營業收入不減。未來薪金另列「營運支出」。初版沒有賣回／降級；若日後加入，退款須引用原交易，不能偽造服務收入。

例：第2天期初$120，提貨／寄貨收入$96，買鞋$120後餘額$96；夜間完成寄貨+$12，今日收入$108、投資支出$120、期末$108，第3天期初$108。關店摘要可暫列$96營收，但封存日報須反映購買及夜間補記，不能把摘要當不可再變動的終帳。

## 6. 員工／分店／自取櫃後期規則

理貨員首版一次搬一件，可暫停自動上架，依玩家允許分區及優先序工作；貨物與目的格先預留，避免搶走玩家手持／確認中的物品。無可用位待命，不卡住通道；收舖停止接新任務，安全完成或退回已有貨後進管理階段。

僱用費與每日薪金分開顯示；排班前保留足夠薪金，可用資金=錢包−預留。付不起可不排班，仍能親自開店，不形成負債。當日薪金只收一次，暫停／讀檔／開管理頁不重收；金額及效益待AI實測。未實裝員工前不新增任何薪金扣款。

分店以玩家實際完成的營業日為結算單位，不以管理頁停留或現實離線時間計費／發錢。自取櫃要有入櫃操作與格位狀態，不是只有被動收益按鈕。兩者均另做最小玩法確認，不能由本框架推定已批准所有數值。

## 7. 子介面結構

沿用青綠／米白像素風、原圖示比例與字體。升級頁頂部只放可用資金與分類；不往營業常駐HUD堆新數字。

- 詢問：標題「今日營業結束」，一句「今晚要升級商店嗎？」，按鈕「查看升級」「暫不升級」；可附目前資金。
- 分類：工具、設備、店鋪、人手、業務。分店與自取櫃在後期分類內展開，不首晚展示整棵複雜升級樹。
- 卡片：名稱／圖示、目前等級、效果前後、價格、條件、生效時點；可買、資金不足、未解鎖、未開放、滿級、處理中各有文字。
- 確認：例如「購買輕便工作鞋 Lv1？ $120；購買後餘額$96；本晚整理起生效；換日前保存」；確認／取消。
- 手機卡片單欄可捲動，資金與「前往貨物上架」固定可見，操作至少48px，不用顏色單獨表示狀態。鍵盤方向鍵／Tab、Enter確認、Esc返回，關閉後焦點回原卡。

這是文字線框，未製作設計稿，未做UI評分或真機可用性宣稱。

## 8. 開發次序與驗收

1. 每日關店詢問與商店殼：跳過／返回／空收貨均不略過管理機會；時間不走。
2. 首個工作鞋Lv1：賺錢→購買→當晚生效→上架→保存→重開保留；資金不足、取消、連按、故障與匯入全部驗證。
3. A/B/C貨架Lv1：獨立升級、可見新格、舊貨位／手持／預留不丟失、選貨及手機捲動通過。
4. 驗證有需求後做收／寄容量、再做一種特殊單；擴建先審地圖。
5. 員工→分店→自取櫃各自獨立最小切片，避免一次實作全部。

新存檔格式需把v0.5有效檔遷移為各升級Lv0、不多發錢、貨物位置不變；先備份，遷移與驗證成功才取代。新增等級、實際容量及效果須互相一致，拒絕等級／容量不符的檔案，不把等級乘算兩次。

必要驗收：零收貨仍可升級；沒有買東西也能開店；買鞋不改NPC；單區加層不改另兩區；收貨容量不改送貨頻率；夜間寄貨加錢後可回店購買；自動／手動換日只提交一次；購後中途匯出／關頁／恢復完整一致；存檔失敗無單邊扣款；新舊分頁不得交叉買；v0.5舊檔升級為Lv0；桌面及手機不誤觸、不遮住繼續按鈕。
